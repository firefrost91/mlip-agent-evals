# Data

## Sources

* `traces.jsonl`: 40 real runs of mini-swe-agent 2.4.2 with Gemini 3.5 Flash on SWE-bench Verified, from
  https://github.com/SWE-bench/20260901_mini-v2.4.2_gemini-3-5-flash (trajectories + per-task test reports). The 40 were
  hand-picked to over-represent failures. Dollar costs are token counts times Google's list price for Gemini 3.5
  Flash in `lab_config.json` (`cost_estimated: true`), because the public run recorded tokens but not cost. The
  trajectories' config shows the model served through an OpenAI-compatible endpoint as `gemini-3-5-flash-fair`;
  we use the submission's label.
* `all_runs.jsonl`: every one of that model's 441 runs: resolved, broken existing tests, and input/output tokens per
  step. The submission has no run for the other 59 of the 500 tasks; they count as unresolved in its 71.8% score.
* `model_results.csv`: per-task resolved and cost for 7 models run with the same agent framework (mini-swe-agent
  v2.0 for the other six), from the
  `per_instance_details.json` files of the bash-only submissions in https://github.com/SWE-bench/experiments.
* `judge_outputs.jsonl` (optional, generated by `judge.py`): the starter judge's verdict on each of the 40 runs, an
  offline fallback for Part 5.

# Schema

These files are the raw recorded runs. `load_traces.py` turns each run into an OpenTelemetry trace in Phoenix
(project `lab11-swebench`): run fields become attributes on the `agent.run` span (`agent.*`, `eval.*`), and, if
`judge_outputs.jsonl` exists, the judge verdicts become `llm_judge` annotations. It also creates Part 5's Phoenix
dataset (`lab11-judge-set`), prompt (`lab11-judge`) and evaluator (`verdict_correct`).

## traces.jsonl

One JSON object per line, one line per (task, run).

| field | meaning |
|---|---|
| `trace_id` | `<instance_id>__r<run>` |
| `instance_id`, `repo` | the SWE-bench task and its GitHub repo |
| `run` | attempt number; always 1 here (the public submission has one attempt per task) |
| `model`, `step_limit` | the LLM behind the agent and the max number of model calls allowed |
| `problem_statement` | the GitHub issue the agent was given |
| `exit_status` | `Submitted`, `LimitsExceeded` (ran out of steps or cost), `RepeatedFormatError`, or an exception name |
| `patch` | the diff the agent submitted (empty if none) |
| `cost_usd`, `n_steps`, `input_tokens`, `output_tokens`, `wall_time_s` | what the run consumed |
| `resolved` | ground truth from the hidden tests (`null` if the grading harness itself errored) |
| `eval_status` | `resolved`, `unresolved`, `empty_patch`, or `missing` (no test report) |
| `patch_applied` | whether the patch applied cleanly to the repo |
| `f2p_pass`, `f2p_fail` | hidden "fail-to-pass" tests (tests for the issue) that pass / still fail |
| `p2p_pass`, `p2p_fail` | existing "pass-to-pass" tests that still pass / now fail (regressions) |
| `steps` | the transcript (below) |
| `cost_estimated` | `true` when cost was computed from tokens rather than recorded |
| `is_sample` | `true` only for placeholder data |

Each element of `steps`:

```json
{
  "i": 7,
  "thought": "The reproduction confirms the bug. The root cause is ...",
  "actions": [{"command": "python reproduce_issue.py", "returncode": 0, "output": "..."}],
  "format_error": false,
  "cost": 0.0205,
  "input_tokens": 12850,
  "output_tokens": 136
}
```

`input_tokens` / `output_tokens` are that model call's own token counts and `cost` is its estimated cost.
`format_error: true` means the model's reply contained no valid command at that step. Long command outputs are
truncated in the middle.

## judge_outputs.jsonl

| field | meaning |
|---|---|
| `trace_id` | joins to traces.jsonl |
| `judge_model` | the LLM used as judge |
| `judge_says_resolved` | the judge's prediction |
| `judge_reason` | the end of the judge's answer, including its VERDICT line |
